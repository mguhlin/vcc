Launch review

Use this record with the full instruction files. It is not a compliance certificate. Use invented data for testing. Do not put secrets or student records in a public report.

  • Local preview or live deployment examined:
  • Actual intended users, task, and age band:

What the application actually does

List inputs, storage, network destinations, sharing, exports, deletion, hosting logs, and third parties. Mark unknowns unverified. Include device storage and URLs even if there is no database.

Checks and evidence

For each row use verified, partially verified, unverified, or not applicable. Explain why. A scanner passing is not proof of full accessibility or security.

Area Status Test and evidence Remaining action / owner
Main educator/learner journey Unverified
Keyboard navigation, focus, and recovery Unverified
Phone layout, 200% text size, and 400% reflow Unverified
Contrast, labels, headings, and alternative text Unverified

Decision

Choose and explain one:

  • Ready for the reviewed scope, with evidence and explicit limits.
  • Ready only as a prototype with invented data.
  • Blocked for student data until listed controls and approvals are resolved.

Before release

List critical blockers, who can resolve them, and the verification needed. Identify tests not run. Separate engineering results from institutional or legal decisions.

After release

Verify the deployed main journey and downloads. Keep a recovery path and a person responsible for dependency updates, access changes, and future material feature reviews.
